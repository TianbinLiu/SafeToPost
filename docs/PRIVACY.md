# Privacy notes

The point of the app is to show what a photo and a caption give away before they are posted, so the
analysis itself stays on the phone.

## What is processed

- The photo bytes you pick or share, the EXIF/JPEG metadata inside them, the decoded bitmap and the
  detected face regions.
- The caption text you type or paste, and the same text when the Safe to Post keyboard is active.
- The cleaned image that you export.

## Where it is processed

- Metadata parsing, face detection, blurring, caption scanning, cleaning and scoring run **on the
  device**. Face detection uses the bundled ML Kit model; no model download is needed.
- No account, no sign-in, no analytics, and no app code that uploads photos or text.
- The APK declares `INTERNET` and `ACCESS_NETWORK_STATE` because the ML Kit/AndroidX dependencies do;
  the documented scan/clean/export path does not use a server. For a strict guarantee, run the test
  build with networking disabled — the flow still works.

## What is kept

- The original photo is never modified; the cleaned copy is a new file in `Pictures/Safe to Post`.
- Metadata, face regions, caption findings and batch thumbnails live in memory for the current
  session. No scan history and no database.
- The selected theme and the keyboard's undo snapshots are in memory/SharedPreferences only; the
  undo stack is discarded when the keyboard session ends.
- The risk score is a heuristic from the listed factors, not a guarantee that a post is safe.

## Permissions

| Permission | Why |
|---|---|
| `android.permission.ACCESS_MEDIA_LOCATION` | Android's photo picker redacts GPS unless this is granted; with it the app can request the original bytes (`MediaStore.setRequireOriginal`) and show real coordinates. Optional — denial only hides the GPS rows. |
| `INTERNET`, `ACCESS_NETWORK_STATE` | Declared by the ML Kit/AndroidX dependencies; not used by the analysis path. |
| `app.safetopost.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | Generated by AndroidX for non-exported receivers. |

The app uses the system picker and MediaStore, so it needs no broad storage permission to read a
picked photo or write the cleaned copy.

## The keyboard

- The IME reads only the focused text field through `InputConnection`; it cannot see photos, other
  apps, or the screen.
- It does not log, persist or upload typed text. The undo stack is in memory, capped at 30 snapshots,
  and is cleared when the input session ends.
- Clean replaces findings in the focused field (with a clipboard fallback if the editor refuses);
  Undo restores the previous text.
- The app does **not** request accessibility or screen-capture permissions; that route was analyzed
  in `IME_FEASIBILITY.md` and deliberately not used.
